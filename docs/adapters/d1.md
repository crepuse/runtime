# Cloudflare D1 Adapter

`@crepuse/runtime/database/sqlite/d1` provides the official adapter implementation for [Cloudflare D1](https://developers.cloudflare.com/d1/) (Cloudflare's serverless native SQLite database).

This adapter wraps the native `D1Database` instance injected by the Cloudflare runtime into a standard [`CrepuseSqliteDatabase`](../database.md#sqlite-extensions), automatically handling parameter normalization, result formatting, binary data conversion, and expectation assertions.

## Installation & Import

Ensure `@crepuse/runtime` is installed in your project:

```bash
npm install @crepuse/runtime
```

Import the factory function from the dedicated subpath:

```typescript
import { createD1Database } from "@crepuse/runtime/database/sqlite/d1";
```

---

## Quick Start

When using in a Cloudflare Workers environment, pass the binding object (e.g. `env.DB`) directly to `createD1Database`:

```typescript
import { createD1Database } from "@crepuse/runtime/database/sqlite/d1";

export interface Env {
    DB: D1Database;
}

export default {
    async fetch(request: Request, env: Env): Promise<Response> {
        // Create the adapter instance
        const db = createD1Database(env.DB);

        // Execute query
        const users = await db.query<{ id: number; name: string }>({
            name: "users.list",
            sql: "SELECT id, name FROM users WHERE active = ?",
            params: [true], // Automatically normalizes true to 1
        });

        return Response.json(users);
    },
};
```

## Core API

### createD1Database

```typescript
function createD1Database(binding: D1DatabaseLike): CrepuseSqliteDatabase;
```

#### Parameters

- `binding`: A D1 database instance matching the `D1DatabaseLike` interface (e.g. `env.DB` in Workers or a mock instance in tests).

#### Returns

- Returns a [`CrepuseSqliteDatabase`](../database.md#sqlite-extensions) instance supporting `run`, `query`, and `batch` methods.

### Type Definitions

```typescript
export interface D1ResultLike {
    success: boolean;
    results: unknown[] | null;
    meta: {
        changes: number;
    };
}

interface D1PreparedLike {
    bind(...values: unknown[]): D1PreparedLike;
    run(): Promise<D1ResultLike>;
}

interface D1DatabaseLike {
    prepare(sql: string): D1PreparedLike;
    batch(statements: D1PreparedLike[]): Promise<D1ResultLike[]>;
}
```

## Features & Guarantees

### Result Normalization & BLOB Handling

Cloudflare D1 natively returns data structured as `{ success: true, results: [...], meta: { changes: 1 } }`. Additionally, in certain serialization scenarios, binary BLOB data may be returned as generic byte arrays (`number[]`).

The built-in `normalizeD1Result` function handles the following automatically:

1. **Structural Validation**: Verifies `success === true`, `meta.changes` is a non-negative safe integer, and `results` is an array or `null`.
2. **Automatic BLOB Reconstruction**: Traverses fields, and when an array containing only byte values (`0~255`) is detected, reconstructs and wraps it into a standard `Uint8Array` to maintain type consistency.
3. **Output Alignment**: Converts the output into the standard `{ rows: [...], affected: changes }` structure.

### Batch Pre-validation Mechanism

When calling `db.batch([...])`:

1. **Atomic Pre-validation**: Before dispatching any statement to the D1 driver, the adapter **pre-validates the validity, expectation format, and all parameters of every statement**.
2. **Fail-Fast**: If any statement contains invalid parameters (e.g. `undefined`, unsafe integers, or sparse arrays), the entire batch throws a `DATABASE_INVALID_STATEMENT` error immediately **without sending any requests to D1**, preventing dirty state or unnecessary network roundtrips.
3. **Sequential Assertion**: After batch execution completes, expectations (`expect`) are evaluated sequentially for each statement.

### Error Context Encapsulation

All exceptions thrown by the underlying D1 driver are caught and wrapped in a `RuntimeError`:

- **Error Code**: Set to `DatabaseErrorCode.ExecutionFailed` (`DATABASE_EXECUTION_FAILED`).
- **Preserved Root Cause**: The original driver error is preserved in `error.cause`.
- **Diagnostic Details**: `error.detail` includes the offending statement name (`statement: statement.name`) or operation type (`operation: "batch"`).

## Usage Examples

### Querying Single & Multiple Records

```typescript
interface UserProfile {
    id: number;
    username: string;
    email: string;
}

// 1. Query multiple records
const activeUsers = await db.query<UserProfile>({
    name: "users.findActive",
    sql: "SELECT id, username, email FROM users WHERE status = ?",
    params: ["active"],
});

// 2. Query a single record (using expect to ensure 0 or 1 row)
const user = await db.query<UserProfile>({
    name: "users.findById",
    sql: "SELECT id, username, email FROM users WHERE id = ?",
    params: [1001],
    expect: { rows: [0, 1] }, // Ensures 0 or 1 row; throws an error if multiple rows return
});
```

### Data Mutations & Affected Rows Assertion

Use `db.run()` for data mutations and assert on the `affected` row count:

```typescript
// Expects exactly 1 row to be updated (e.g. preventing missing records or concurrency anomalies)
const result = await db.run({
    name: "users.updateEmail",
    sql: "UPDATE users SET email = ? WHERE id = ?",
    params: ["new_email@example.com", 1001],
    expect: { affected: [1, 1] },
});

console.log("Update succeeded, affected rows:", result.affected);
```

### Batch Operations

Execute multiple statements in a single network roundtrip using `db.batch()`:

```typescript
const [insertResult, logResult] = await db.batch([
    {
        name: "orders.create",
        sql: "INSERT INTO orders (id, amount, user_id) VALUES (?, ?, ?)",
        params: ["order_123", 99.5, 1001],
        expect: { affected: [1, 1] },
    },
    {
        name: "logs.record",
        sql: "INSERT INTO audit_logs (action, target_id) VALUES (?, ?)",
        params: ["create_order", "order_123"],
        expect: { affected: [1, 1] },
    },
]);
```

### Binary Data (BLOB) Read & Write

The D1 adapter provides native, transparent support for `Uint8Array`:

```typescript
// Write BLOB data
const salt = new Uint8Array([0x01, 0x02, 0x03, 0x04]);

await db.run({
    name: "credentials.insert",
    sql: "INSERT INTO credentials (user_id, salt) VALUES (?, ?)",
    params: [1001, salt],
});

// Read BLOB data (automatically restored to Uint8Array)
const rows = await db.query<{ user_id: number; salt: Uint8Array }>({
    name: "credentials.findByUserId",
    sql: "SELECT user_id, salt FROM credentials WHERE user_id = ?",
    params: [1001],
});

console.log(rows[0].salt instanceof Uint8Array); // true
```
